## 1. What This Project Is & The Prime Directive

XLMem measures whether LLM agent memory survives a user switching languages between sessions (Hindi ↔ English, including code-switched "Hinglish"). It is a **research measurement harness**, not a product and not a memory system. We do not build a memory framework; we measure existing ones (Mem0, Letta/MemGPT, A-MEM).

### The Prime Directive

> **MEASUREMENT CORRECTNESS OUTRANKS EVERYTHING ELSE** — features, speed, elegance.

This is not a product. Nobody cares if the code is fast, clever, or feature-rich. They care whether the numbers mean what the paper claims they mean. A fast harness that measures the wrong thing is worthless.

Before any change, ask: **"Could this alter what a metric measures?"**
If yes → **STOP and flag it explicitly instead of proceeding.** Silent semantic drift in an evaluation harness is the fatal failure that destroys a paper after the experiments are finished, when there is no time left to redo them. If a change could alter what a metric means, it needs explicit justification.

## 3. Expensive Mistakes, Ranked

1. **Launching a full sweep without a smoke run** — burns 60–100 GPU-hours on a broken config.
2. **Changing a metric without re-scoring prior runs** — silently makes results incomparable across runs.
3. **Adding a paid API call** — invalidates the zero-cost claim in the PRD and violates lab ethics/agreements.
4. **Special-casing a framework inside the runner** — leaks abstractions and invalidates cross-framework comparisons.
5. **Reporting a single-seed number** — scientifically invalid; reviewers will reject it.

---

## 4. Hard Rules & Non-Negotiable Invariants

These are not style preferences. Breaking them invalidates results:

1. **No paid APIs.** No OpenAI, Anthropic, Gemini, Cohere — not for generation, not for judging, not "just for a quick test." Local open models only.
2. **All model calls go through `xlmem/llm/client.py`.** Never call Ollama, vLLM, or `transformers` directly from anywhere else. One chokepoint keeps logging, seeding, and token accounting consistent.
3. **The runner NEVER judges.** It records raw responses. Every hit/miss decision lives in `xlmem/scoring/` and runs offline from logs.
4. **Run logs are append-only and immutable.** Re-scoring reads logs; it never rewrites them. Re-scoring must never require re-running the GPU.
5. **Never report a single seed.** Any number reported in `results/` is mean ± std over ≥3 seeds.
6. **Language is the only variable.** If you change facts, session structure, or seeds between two compared conditions, the comparison is void.
7. **`dump()` is a hard requirement for any memory framework.** It must return the **full** store, not top-k. Duplication and false-merge measurements depend on store inspection. A framework without `dump()` is ineligible.
8. **Facts are template-authored, never generated by the model under test.** Model-generated facts contaminate measurement with the model's generation biases.
9. **Never commit** model weights, `runs/` logs, or `.env`. Commit `results/` (aggregated) and `data/` (the benchmark).
10. **Pin versions.** Memory-framework APIs change often. Any dependency bump is its own commit with the conformance suite re-run.
11. **Check Write Fidelity first.** A fact missing from `dump()` is a WRITE failure, not a retrieval failure. Never conflate them.

```bash
# Environment (never install into base)
conda env create -f environment.lock.yml
conda activate xlmem

# Local model server
ollama serve &
ollama pull qwen2.5:7b-instruct
```

`check_env` verifies: CUDA available · VRAM ≥ 14 GB free · Ollama reachable · embedder loads · HuggingFace reachable (or cache warm).

## 7. Code Style & Review Checklist

- **Python 3.11**, type hints on every public function
- `ruff` for lint + format (line length 100); `mypy` clean on `xlmem/`
- **Dataclasses** for data models — `frozen=True` for anything representing ground truth (`Fact`, `Turn`)
- **Pydantic** for config validation only
- No bare `except:` — catch specific exceptions and log context
- Docstrings on public functions: one line of *what*, one of *why* if non-obvious
- Prefer pure functions in `scoring/` and `analysis/` — they must be testable without a GPU

**Vocabulary Consistency:** Use the terminology from `ARCHITECTURE.md` consistently:
`plant`, `filler`, `probe`, `correction`, `store_lang`, `probe_lang`.
Don't invent synonyms. Metric names in code must match metric names in the paper.

### Invariants Checklist for Code Review

```
[ ] All model calls route through xlmem/llm/client.py
[ ] Runner contains no hit/miss logic (runner records; scoring judges)
[ ] Metrics are pure functions, testable without a GPU
[ ] Run logs are append-only and immutable
[ ] Any reported number has >= 3 seeds behind it
[ ] Compared conditions differ ONLY in language
[ ] dump() returns the entire store, not top-k
[ ] Write Fidelity is checked first before attributing retrieval failure
```

## 8. Working Style & Boundary Discipline

- **Prefer small, verifiable steps.** Write the spec, then the test with hand-computed values, then the implementation. Metric bugs are nearly invisible; a plausible-looking wrong number is far worse than a crash.
- **Absorb every framework quirk inside its adapter.** Never let a quirk leak into the runner — that invalidates cross-framework comparisons. If a quirk cannot be hidden behind the interface, document it in `ARCHITECTURE.md` §16 as a known confound.
- **When results look surprising:** Do NOT "fix" them. Surprising results are the point. Check the log first — verify whether the fact was actually written (`Write Fidelity`) before concluding retrieval failed.
- **When launching long runs:** Confirm the smoke run passed, confirm ≥14 GB VRAM free, confirm the config is committed, and run under `tmux`/`screen`.

### What to Ask About Rather than Assume

These are **research design decisions**, not implementation details. They are owned by the student and guide:
- Anything that changes a metric's definition, formula, or scope
- Dropping a framework, model, or language direction from the matrix
- Changing seeds, fact counts, or session structure between compared conditions
- Whether a new confound should be reported as a covariate or controlled away

## 9. Adding a Memory Framework

1. Create `xlmem/adapters/<name>_adapter.py` implementing `MemoryAdapter`
2. Set `supports_dump = True` — verify it returns the **full** store, not top-k
3. Register in `xlmem/adapters/__init__.py`
4. Run `pytest tests/test_adapter_contract.py -k <name>` — must pass unchanged
5. Pin the framework version in `environment.lock.yml`

---

## 10. Adding a Metric

1. Implement as a pure function in `xlmem/scoring/`
2. Add a unit test with **hand-computed** expected values (not model-generated)
3. Document formula and which memory operation it tests in `METRICS_SPEC.md` and `ARCHITECTURE.md` §8
4. Re-score existing runs — new metrics must never require re-running experiments

---

## 11. Testing Expectations

| Layer | Requirement |
|---|---|
| Unit | Every metric has a hand-computed fixture test |
| Contract | Every adapter passes the identical conformance suite |
| Golden | 10-fact mini-benchmark with a stubbed LLM produces known metrics |
| Smoke | 5-fact real-model run completes < 5 min |

**Before any experiment run:** `pytest tests/ -m "not gpu"` must be green. Debugging a 3-hour GPU run because of a broken metric is the most expensive mistake available in this project.

---

## 12. Experiment Discipline

- **Never launch a full sweep without a smoke run first.** Full matrix ≈ 60–100 GPU-hours.
- Every run writes: config hash, git SHA, package versions, seeds, all prompts and raw responses.
- Long runs go in `tmux`/`screen` — SSH drops must not kill an overnight batch.
- Log GPU memory at start; abort early if < 14 GB free rather than OOM-ing at hour two.
- One config = one `runs/<experiment_id>/` directory. Never write two runs into one directory.

## 14. Things That Look Like Bugs But Aren't

- **Frameworks consolidate at different times.** Some merge on write, some on explicit call. This is why we snapshot before *and* after every phase — don't "fix" it by forcing uniform timing.
- **Hindi prompts produce more tokens than English.** Expected (tokenizer behaviour). Track as a covariate; don't normalise it away.
- **Small variation at temperature 0.** Batching and kernel nondeterminism. This is why ≥3 seeds are mandatory.

If a decision could change what a metric means — pause and ask rather than guessing. Silent semantic drift in an evaluation harness is the failure mode that invalidates a paper after the experiments are done.
